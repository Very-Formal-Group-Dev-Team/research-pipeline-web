## Student

### Overview

Your student account lets you manage your research project from first draft through defense. You can create a project and invite teammates, join an existing group with a project code, or accept an invitation. Upload papers with version history, request adviser feedback, exchange inline comments on the manuscript, track meetings and defenses, and stay on top of invitations and review updates through notifications.

### Key tasks

- Create a new research project (Thesis or Capstone) and invite collaborators and advisers
- Join an existing project using a project code, or accept a pending invitation
- Upload and version research papers with commit messages and document previews
- Request adviser review on your latest paper version with a focus note
- Open **Comment** on any paper version to read adviser feedback and add inline notes
- Manage your team: share your project code, approve join requests, and invite members
- Edit your abstract, project details, and keywords (including AI-assisted keyword extraction)
- Check **Events** for institution announcements, adviser meetings, and defense schedules
- Join online meetings and defenses; revisit recordings and transcripts afterward
- Respond to notifications about invitations, reviews, comments, and schedule changes

### Sidebar capabilities

| Area | What you can do |
|------|-----------------|
| Dashboard | Announcements, join-a-project card, pending invitations, quick links |
| My Projects | Browse, create, and manage projects and paper versions |
| Document comments | Inline comments on paper versions with replies and status tracking |
| Notifications | Invitations, reviews, comments, and project activity |
| Events | Institution events, meetings, and defenses |
| Recordings | Meeting and defense recordings with transcripts |
| Profile | Display name, avatar, and status |

### Workflows

**Start or join a research project**

1. From the dashboard, choose **Create Project** or enter a project code under **Join a Project**.
2. If invited, accept the invitation from the dashboard, **My Projects**, or **Notifications**.
3. After joining, open the project to view your project code, team, and paper history.
4. Share your project code with teammates or invite them from the project page.

**Submit a paper version for adviser review**

1. Open your project and go to **Paper Version History**.
2. Generate a template or upload your first DOC/DOCX/PDF file.
3. Upload a new version with a commit message describing what changed.
4. On the latest upload, choose **Request Review** and add a focus note (at least 20 characters).
5. Watch for a review notification. Withdraw a pending request if you need to upload a correction first.

**Work with inline document comments**

1. From **Paper Version History**, choose **Comment** on the version you want to discuss.
2. Read adviser notes in the comments sidebar. Click a comment to jump to its location.
3. Select text in the preview to add your own comment or reply to a thread.
4. Address comments marked **needs revision** in your next upload.
5. Filter the sidebar by status or author.

**Prepare for a meeting or defense**

1. Open **Events** and check the **Meetings** or **Defenses** tab.
2. Expand defense cards for location, adviser, and panelist details.
3. Use **Join Meeting** or **Join Defense** when the session is online.
4. After the session, open **Recordings** or the **Transcription** link.

### Tips

- Three ways to join: create a project, accept an invitation, or enter a project code.
- Only the latest uploaded paper version can be sent for adviser review.
- Inline comments are anchored to selected text; editing that passage in a new version may flag comments as modified or orphaned.
- Projects lock when marked **Completed** or **For Publication**.
- Research stages are updated by your adviser; you can view but not change them.
- Use cross-referencing on your project to discover related studies after setting keywords.

## Adviser

### Overview

You oversee research projects assigned to you: track progress, move projects through research stages, review paper versions with inline comments, book meetings with students, and monitor defense schedules. The dashboard surfaces pending paper reviews and recent advisee activity. You can join projects with a project code or accept invitations from student leaders.

### Key tasks

- Review advisee projects, advance research stages, and read abstracts and details
- Leave inline comments on paper versions; resolve, request revision, or reopen threads
- Mark paper versions as reviewed after students submit review requests
- Book, edit, cancel, and complete adviser meetings
- Manage project teams: invite members, remove collaborators, transfer main adviser role
- Join advisee projects via project code or accept invitations
- Monitor pending reviews and recent activity from your dashboard
- View defense schedules and institution events in **Events**
- Create and maintain evaluation rubrics for proposal, midterm, and final defenses
- Join online meetings and defenses; revisit recordings and transcripts

### Sidebar capabilities

| Area | What you can do |
|------|-----------------|
| Dashboard | Advisee stats, pending reviews, recent activity, schedule calendar |
| My Advisees | Advised projects with search and filters; open any project for papers and meetings |
| Document comments | Inline feedback with resolve, revision request, and thread replies |
| Notifications | Review requests, comments, invitations, schedule alerts |
| Events | Institution events, meetings, and defenses for your advisees |
| Recordings | Recordings and synced transcripts |
| Rubrics | Create and edit defense rubrics (weights must total 100%) |
| Profile | Display name, avatar, and availability status |

### Workflows

**Review a student paper with inline comments**

1. Check **Pending Reviews** on your dashboard or open the review notification.
2. Open the project and choose **Review & comment** on the requested version.
3. Read the student's focus note and use the document preview to compare changes.
4. Select text to leave inline feedback. Use **Request revision** or **Resolve** as appropriate.
5. When finished, choose **Mark reviewed** (you will be warned if open comments remain).

**Schedule a meeting with advisees**

1. Open the project **Meetings** section or use the **Meeting Schedule** page.
2. Choose **Book a Meeting** and set date, time, modality, and participants.
3. Edit, cancel, or mark complete as needed. Join online sessions from the meeting card.

**Move a project through research stages**

1. Open the advisee project from **My Advisees**.
2. In **Research Stage**, select the next stage (e.g. Approved, Ongoing, For Pre-Defense).
3. Students see the updated stage and receive a notification.

### Tips

- You cannot upload paper versions — students upload; you review and mark as reviewed.
- Formal defenses are scheduled and verified by coordinators; you view schedules in **Events**.
- **Pending Reviews** on the dashboard is the fastest way to see papers needing attention.
- Rubrics you create can be selected by coordinators when scheduling defenses.
- Use the document preview diff to spot changes between versions without downloading each file.

## Coordinator

### Overview

You manage research activity across your institution: set up courses and assign faculty advisers, manage sections, schedule and verify defenses, publish institution events, and maintain evaluation rubrics. The dashboard highlights pending defense requests. You can browse all projects institution-wide for oversight without day-to-day advising.

### Key tasks

- Create courses and assign or remove faculty advisers for each course
- Manage institution **Sections** for organizing student groups
- Schedule institution events (workshops, orientations, deadlines)
- Schedule formal defenses with panelists, rubrics, venues, and modalities
- Review pending defense requests: approve, move to a new slot, or reject
- Manage approved defenses: complete, cancel, or batch-assign time slots
- Browse all projects by adviser or institution-wide
- Create and maintain defense rubrics
- Track defense verification and institution events via notifications

### Sidebar capabilities

| Area | What you can do |
|------|-----------------|
| Dashboard | Institution stats, defense verification shortcuts, schedule calendar |
| Events | Institution events and defense pipeline (Pending / Approved tabs) |
| Notifications | Defense verification, schedule changes, event alerts |
| Recordings | Institution meeting and defense recordings |
| Courses | Create courses and assign faculty advisers |
| Sections | Manage institution sections |
| All Projects | Read-only oversight by adviser or institution-wide |
| Rubrics | Institution-wide defense rubrics (weights must total 100%) |
| Profile | Display name, avatar, and status |

### Workflows

**Set up courses and advisers**

1. Open **Courses** and choose **New Course**.
2. Expand a course and use **Add Adviser** to link faculty.
3. Remove advisers when assignments change.

**Schedule and verify a defense**

1. From **Events**, choose **Schedule** → **Defense**.
2. Choose by course or specific groups; set type, rubric, date, location, and modality.
3. Assign panelists before submitting.
4. Pending defenses appear under **Pending** — approve, move, or reject.
5. Approved defenses move to **Approved** for completion, cancellation, or batch time-slot assignment.

**Publish an institution event**

1. From **Events**, choose **Schedule** → **Event**.
2. Fill in title, description, date, time, and location.
3. Edit, cancel, or mark complete as the date passes.

**Monitor institution-wide progress**

1. Open **All Projects** — switch between **By Adviser** and **All Projects**.
2. Review research stage badges, course assignments, and project codes.
3. Follow up with advisers before defense season.

### Tips

- Faculty advisers are managed under **Courses**, not a separate advisers menu.
- **Pending** is for defenses awaiting your decision; **Approved** is for confirmed schedules.
- Use **Assign Defense Batches** when multiple groups defend on the same day.
- **All Projects** is read-only — advisers handle day-to-day project management.
- Rubrics must total 100% across criteria weights before use in defense scheduling.

## Admin

### Overview

You configure the institutions and academic programs that power Archivum. Register institutions, manage programs, assign user roles and institutions, review the audit log, and enable or disable platform access. Coordinators and users under each institution rely on this setup before they can manage courses, projects, and defenses.

Admin accounts do **not** manage courses, defenses, or projects directly — that happens at the coordinator level.

### Key tasks

- Register new institutions with a name and institution code
- Enable or disable institutions when onboarding schools or retiring access
- Manage each institution's program catalog (students pick programs when creating projects)
- Add, edit, and activate or deactivate individual programs
- List, search, and filter users across the platform
- Assign user roles, institutions, and active/inactive status
- Review the system and project audit log
- Use the dashboard as a quick entry point to institutions, users, and audit

### Sidebar capabilities

| Area | What you can do |
|------|-----------------|
| Dashboard | Platform overview with links to institutions, users, and audit |
| Institutions | Create institutions, toggle Active/Inactive, manage programs |
| Users | Search users, assign role and institution, activate/deactivate accounts |
| Audit Log | Read-only merged system and project activity log |
| Profile | Display name, avatar, and status (email and role are fixed) |
| Settings | Account and display preferences |

### Workflows

**Onboard a new institution**

1. Open **Institutions** and choose **New Institution**.
2. Enter the institution name and code, then save.
3. Open **Manage** on the new institution to add programs.
4. Confirm the institution is **Active** so coordinators and users can sign in.

**Maintain a program catalog**

1. From **Institutions**, open **Manage** on the target school.
2. Under **Programs**, add each degree or track with name, code, and description.
3. Toggle programs **Active** or **Inactive** — inactive programs won't appear for new projects.

**Manage a user account**

1. Open **Users** and search or filter by role, institution, or status.
2. Open a user to view details.
3. Assign or change role, institution, and active status as needed.
4. Deactivated users cannot sign in until reactivated.

**Review platform activity**

1. Open **Audit Log** to view system and project events.
2. Use filters to narrow by date, institution, or actor when available.

**Retire or pause an institution**

1. Open **Institutions** and locate the school to disable.
2. Toggle the institution to **Inactive** and confirm.
3. Re-enable later if access should be restored.

### Tips

- Inactive institutions block coordinators and users until re-enabled.
- Inactive programs are hidden for new projects; existing projects keep their program.
- Keep institution codes stable — they are identifiers across the platform.
- Coordinators need institutions and programs set up before students can classify projects correctly.
- For day-to-day research operations, direct users to coordinator accounts.
